One row per try, and at most one that worked. Failures are rows too: a table holding only the readings that worked can be quoted to say anything.

extracted_fields2

Nobody edits a reading, so the reading is the only writer here. An uncertain row keeps the model's value for the accuracy work, and every screen treats it as no value at all.

Every prompt sent to a model, so an accuracy figure can be reproduced and a wrong reading argued about with the evidence on the table.

tasks46

Her yes writes this row. state is the tick, the one fact a person controls. Overdue is never stored: it is arithmetic done while a screen draws, from the tick and today's date in her zone.

reminders45

  • id
  • task_id → tasks
  • scheduled_for
  • channel
  • status
  • sent_at
  • created_at
Rows, not a rule evaluated when somebody looks. Ticking writes nothing here. When a row's moment arrives, the clock reads the task: still open means send, already done means write skipped.
